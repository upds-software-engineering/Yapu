VISTA ARQUITECTÓNICA · DIAGRAMA 1 ⏱ 0:45 - 1:15 · Emmanuel Ponce

Topología de 4 Capas y Protocolos Reales

1. Capa de Cliente (Astro PWA)

Astro SSG + Islands: Cero JavaScript innecesario en el cliente. FCP < 1.8s (RNF-001).

Service Worker & Workbox: Intercepta peticiones HTTP, responde desde Cache API e IndexedDB sin depender de internet.

Motor IA en TypeScript: Algoritmo determinista local (< 10MB memoria de trabajo).

2. Capa Nube & 3. Capa VPS

Google Firebase (BaaS): Firebase Auth con JWT claims (`estudiante`, `docente`, `admin`). Cloud Firestore NoSQL con reglas declarativas estrictas.

VPS Linux Debian (UPDS): Nginx HTTP/2 sirviendo activos WebP optimizados (< 100KB, RS-001) y endpoint de datos abiertos CSV/JSON (RS-004).

Canal Criptográfico: Todo el tráfico remoto viaja cifrado bajo HTTPS con TLS 1.3 AES-GCM-256.

Aclaración Arquitectónica: La comunicación cliente-servidor es desacoplada mediante llamadas HTTP estándar interceptadas por el Service Worker; no se introducen rombos de decisión condicional en la red.

INNOVACIÓN TÉCNICA · DIAGRAMA 6.1 Y 9.1 ⏱ 2:40 - 3:00 · Emmanuel Ponce

Motor de IA Determinista vs. LLMs Comerciales

¿Por qué NO usar un LLM (ChatGPT/Claude)?

  • Alucinaciones Críticas: Invención de sufijos aglutinantes inexistentes o mezclas con aymara.
  • Costos de API Inviables: Ruptura de la restricción de presupuesto \$0 (SRS 3.3).
  • Imposibilidad Offline: Inaccesible en escuelas rurales sin conectividad activa.

Algoritmo Determinista en TypeScript

  • Permutación Morfológica: Aplicación de marcas de caso controladas (locativo -pi, alativo -man, ablativo -manta).
  • Distractores Verosímiles: Filtro estricto que exige misma categoría gramatical y mismo campo semántico.
  • Fisher-Yates Shuffle: Mezcla aleatoria determinista sin alterar la respuesta canónica.
SOBERANÍA CULTURAL · DIAGRAMA 6.2 ⏱ 3:00 - 3:15 · Emmanuel Ponce

Doble Moderación y Principio de Cuatro Ojos

Regla Inviolable: autor_id != validador_id

Para proteger la autenticidad dialectal del quechua sureño Collao (Chuquisaca), ninguna oración entra al motor de IA sin ser certificada por un segundo docente independiente.

1. Ingreso del Reactivo

Docente 1 crea la oración con texto quechua, traducción y campo obligatorio de contexto cultural. Queda en estado pendiente.

2. Revisión Ciega

Docente 2 inspecciona la ortografía normalizada y la pertinencia etnográfica. Puede aprobar, editar o rechazar con motivo pedagógico.

3. Despliegue

Al alcanzar estado aprobada, la oración se sincroniza automáticamente al banco local de los estudiantes para el generador de exámenes.

VISTA DINÁMICA · DIAGRAMAS 7 Y 9.2 ⏱ 3:15 - 3:45 · Jhoel Cruz

Secuencia Temporal y Resiliencia Offline-First

Flujo de Evaluación y Persistencia Desacoplada

1. Estudiante rinde examen → 2. Motor TS califica en local → 3. Guarda en IndexedDB de forma síncrona → 4. Desbloquea nivel en UI.

Escenario 1: Modo Sin Conexión (Offline)

La evaluación se encola en SyncQueueRecord en IndexedDB. El Service Worker registra una tarea en la Background Sync API del navegador. Cero mensajes de error para el estudiante.

Escenario 2: Restablecimiento de Red (Online)

El navegador emite el evento online. El Service Worker despierta, lee la cola de IndexedDB y ejecuta un Firestore Batch Write atómico. Confirma y marca los registros locales como sincronizados.
